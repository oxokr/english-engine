# /handoff — 세션 연속성 갱신

다음 세션이 *혼란·노이즈 없이* 이어받도록 `.claude/SESSION_STATE.md` 를 갱신한다. 이 파일은 SessionStart hook이 매 세션 자동 주입하므로, 여기 정확히 쓰면 다음 세션이 변수 없이 같은 맥락을 받는다.

## 너(Claude)가 지금 할 일

`.claude/SESSION_STATE.md` 를 **덮어쓰기**(Write)로 갱신하라. git 사실(브랜치·커밋·dirty)은 hook이 매번 live로 계산하니 **여기 적지 마라** — 너는 *기계가 모르는 것*, 즉 **서사적 맥락**만 남긴다. 아래 틀을 정확히 채워라:

```markdown
# SESSION_STATE — 롤링 핸드오프 (마지막 갱신: <오늘 날짜>)

## 지금 무엇을 하던 중인가 (한 문단)
<현재 작업의 핵심. 예: "결제 모듈 리팩터 중 — 3개 핸들러 중 2개 마이그레이션함">

## 왜 이렇게 하고 있나 (결정·근거)
<이 방향을 택한 이유, 직전에 바뀐 결정. 예: "X 대신 Y로 결정. 이유는 Z">

## 다음 한 걸음 (구체적으로, 단계가 여럿이면 순서대로)
<다음 세션이 바로 시작할 행동. 예: "1. 핸들러 C 마이그레이션 → 2. 통합테스트 → 3. 커밋">

## 지금 건드리면 안 되는 것 (다른 세션·진행중·되돌리기 어려움)
<병렬 세션이 작업 중인 파일, 미완으로 두면 안 되는 것. 없으면 "없음">

## 함정·주의 (이번 세션에서 새로 배운 것)
<다음 세션이 모르면 시간 낭비할 것. 예: "X는 외부 API라 키 필요 / Y 파일은 자동생성이라 직접 수정 금지">
```

## 규율
- **확정 사실만** — 추측·미완을 "됨"으로 적지 마라.
- **간결하게** — hook이 매번 주입하므로 길면 노이즈. 각 절 2~4줄.
- git 사실·계획 단계는 hook이 자동 주입하니 중복 금지.
- 갱신 후 사용자에게 "SESSION_STATE 갱신함, 다음 세션은 자동 로드된다"고 한 줄 보고.

작성이 끝나면 `.claude/SESSION_STATE.md` 만 바뀐다(추적 파일·소스 무변경 → 다른 세션과 충돌 0).
